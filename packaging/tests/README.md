# tests

Everything that exists only to verify the packaging tooling. Nothing here is a product and nothing
here is released.

```
make_fixtures.sh          generate the fixture packages and their rosdep mapping
build_fixtures.sh         build every fixture into a .deb, using builder/build_pkg.sh
fixtures/                 seven minimal packages, generated
probes/                   two hand-written packages that test dependency resolution
install_test.sh           install from the local flat repository
install_from_archive.sh   install from the signed archives, keyring and Signed-By
```

## The fixtures

`make_fixtures.sh` writes `fixtures/`. The names are deliberately generic: `product_a`, `product_b`,
`product_c`, a `combined` metapackage, a `skill`, an `sdk` and a shared `core`.

What matters is the shape, not the names. `duatic_fixture_combined` depends on
`duatic_fixture_product_a` and `duatic_fixture_product_b`, the way a composite entitlement carries
the entitlements it is made of. Those two live in different archive roots and are authorised
separately, so installing the combined package has to pull from both. If the entitlement model and
the archive layout ever disagree, that install fails. That is the coherence check, and the only
reason the dependency exists.

Regenerate them after changing the generator:

```bash
./make_fixtures.sh                              # mappings for jazzy and kilted
./build_fixtures.sh                             # builds for jazzy
ROS_DISTRO_TARGET=kilted ./build_fixtures.sh    # and for kilted
```

`ROS_DISTROS` selects which mappings `make_fixtures.sh` writes, `ROS_DISTRO_TARGET` and
`OS_VERSION` select what `build_fixtures.sh` builds. The fixture sources themselves are
distro-independent; only the Debian names and the rosdep mapping change.

## The probes

`probes/duatic_probe` compiles against a header generated by a package outside the public rosdistro
index, so it fails to build when a rosdep mapping is missing. `probes/duatic_probe_exec` declares the same dependency at
runtime only and never compiles against it, which is the shape a Python node or a launch file has.
Together they show whether an unresolved rosdep key is treated as leniently for run dependencies as
for build ones.

Unlike the fixtures these are written by hand, so they are not regenerated.

## The install checks

Each exits non-zero on failure, so they work as checks rather than something to read.

```bash
docker run --rm -it \
  -v "$PWD/../builder:/builder:ro" \
  -v "$PWD:/tests:ro" \
  ros:jazzy-ros-base \
  /tests/install_test.sh [package]
```

`install_from_archive.sh` takes `public` to assert the private package is *not* installable.

Checks that exercise a gateway, rather than the archive tree itself, live with the gateway.
